# 预充值模式（to C）

TokenHub 提供两种部署模式，在 **系统设置 → 部署模式** 中切换：

- **企业内部**（默认）：现有后付费模型。额度策略按 API Key、用户或项目限制请求数、Token 数和日/月成本，不做余额管控。
- **面向公众 to C**：预充值管控。网关请求只有在扣费钱包余额大于 0 时才放行，请求完成后按租户计价扣减余额。

## 钱包

钱包分为两级：

- **个人钱包**：有属主（`owner_user_id`）的 API Key 从属主的个人钱包扣费；无属主的共享 Key 从所属**项目钱包**扣费。
- 钱包按需创建：首次管理员充值、调账或兑换码入账时创建。to C 模式下没有钱包等同余额为 0，因此切换模式前应先为必须继续运行的钱包注资。
- **豁免**：把钱包标记为不参与余额管控（用于公开部署中的内部用户或项目）。豁免钱包仍出现在报表里，但请求不会检查或扣减它。

拦截发生在准入阶段：余额不大于 0 的钱包的新 `/v1/*` 请求会收到 HTTP 402 `insufficient_balance`。在途请求正常结算，可能把余额扣成小幅负数，下一个请求随即被拦截。余额与金额均为 USD，与模型计价一致，保留 6 位小数。每笔请求的扣费按请求 ID 幂等。

## 充值兑换码

管理员按批次生成一次性兑换码（数量、面值、可选过期时间、备注）。完整码只在生成时返回一次——与 API Key 密钥一样无法再次显示。用户在 **我的钱包** 中兑换；兑换会锁定码记录，并发兑换不会重复入账。未使用的码可以作废。

## 自助注册

to C 模式下，**开放自助注册** 设置会在登录页开放注册入口。注册需要邮箱和 8–72 位密码；用户名可选（缺省取邮箱前缀）。新账号默认 `user` 角色并进入个人控制台，可自助创建 API Key（无项目时使用默认项目）和兑换充值码。注册按客户端 IP 限流。

## 管理端接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET, POST | `/api/admin/wallets` | 钱包列表；为用户或项目创建（并可选注资）钱包 |
| POST | `/api/admin/wallets/{id}/adjust` | 手动充值（正数）或扣减（负数），可附备注 |
| PATCH | `/api/admin/wallets/{id}` | 设置或取消豁免 |
| GET | `/api/admin/wallets/{id}/transactions` | 钱包流水 |
| GET, POST | `/api/admin/topup-codes` | 兑换码列表（仅前缀）；批量生成（完整码仅返回一次） |
| POST | `/api/admin/topup-codes/{id}/revoke` | 作废未使用的码 |

钱包管理需要 `wallet` 资源权限（平台管理员和团队负责人）。所有钱包与兑换码变更都会记录管理员审计事件。

## 自助接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/my/wallet` | 当前用户余额与最近流水 |
| POST | `/api/admin/my/wallet/redeem` | 兑换充值码 |
| GET | `/api/admin/auth/registration` | 登录页使用的公开开关 |
| POST | `/api/admin/auth/register` | 公开自助注册（to C 模式且开关开启） |

## 控制台页面

- **成本治理 → 预充值钱包**（管理员）：钱包列表、手动调账、豁免开关、流水抽屉。
- **成本治理 → 充值兑换码**（管理员）：批量生成（一次性显示、复制、导出）与作废。
- **我的资源 → 我的钱包**（普通用户）：余额卡片、兑换码入账、个人流水。

## 说明与边界

- 在线支付、发票、人民币计价和按请求预留本期不做；在途请求造成的小幅透支属于设计内行为。
- 注册限流为进程内实现。多实例部署建议在注册入口前增加边缘限流代理。
