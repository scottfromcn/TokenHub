# プリペイド課金（to C モード）

TokenHub には **システム設定 → デプロイモード** で切り替える 2 つのモードがあります。

- **社内利用**（既定）：既存の後払いモデル。クォータポリシーが API キー・ユーザー・プロジェクトごとにリクエスト数、トークン数、日次/月次コストを制限し、残高は管理しません。
- **一般向け to C**：プリペイド管理。課金対象ウォレットの残高が正である場合のみゲートウェイリクエストを許可し、リクエスト完了時にテナント価格で残高を減算します。

## ウォレット

ウォレットは 2 階層あります。

- **個人ウォレット**：所有者（`owner_user_id`）付きの API キーは所有者の個人ウォレットから支払います。所有者のいない共有キーはキーのプロジェクトの**プロジェクトウォレット**から支払います。
- ウォレットは必要時に作成されます。管理者による初回チャージ、調整、またはコード引き換え時に作成されます。to C モードではウォレットがない場合は残高 0 とみなされるため、モード切替前に継続が必要なウォレットへ入金してください。
- **免除**：ウォレットを残高管理の対象外にします（一般向け環境の内部ユーザーやプロジェクト向け）。免除ウォレットはレポートに表示されますが、リクエストのチェックや減算は行われません。

拒否はアドミッション時点で行われます。残高 0 以下のウォレットからの新しい `/v1/*` リクエストは HTTP 402 `insufficient_balance` で拒否されます。実行中のリクエストは通常どおり決済され、残高がわずかに負になることがあります。残高・金額は USD で、モデル価格と一致し、小数 6 桁に丸められます。各リクエストの減算はリクエスト ID ごとに冪等です。

## チャージコード

管理者はバッチ（数量、額面、任意の有効期限、メモ）で使い切りコードを生成します。コード全文は生成時に一度だけ返されます。API キーシークレットと同様に再表示できません。ユーザーは **マイウォレット** で引き換えます。引き換えはコード行をロックするため、同時引き換えで二重入金は発生しません。未使用のコードは無効化できます。

## セルフ登録

to C モードで **セルフ登録を許可** を有効にすると、ログイン画面に登録入口が表示されます。登録にはメールアドレスと 8〜72 文字のパスワードが必要です。ユーザー名は任意（未入力ならメールプレフィックス）です。新規アカウントは `user` ロールで個人コンソールに入り、自分の API キー作成（プロジェクト未所属なら既定プロジェクト）とコード引き換えができます。登録はクライアント IP ごとに制限されます。

## 管理者用エンドポイント

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET, POST | `/api/admin/wallets` | ウォレット一覧。ユーザー/プロジェクトのウォレット作成（任意で入金） |
| POST | `/api/admin/wallets/{id}/adjust` | 手動チャージ（正）または減算（負）。メモ付き |
| PATCH | `/api/admin/wallets/{id}` | 免除フラグの設定/解除 |
| GET | `/api/admin/wallets/{id}/transactions` | ウォレット明細 |
| GET, POST | `/api/admin/topup-codes` | コード一覧（プレフィックスのみ）。バッチ生成（全文は一度だけ返却） |
| POST | `/api/admin/topup-codes/{id}/revoke` | 未使用コードの無効化 |

ウォレット管理には `wallet` リソース権限が必要です（プラットフォーム管理者とチームリーダー）。ウォレットとコードのすべての変更は管理者監査イベントに記録されます。

## セルフサービスエンドポイント

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/api/admin/my/wallet` | 自身の残高と最近の明細 |
| POST | `/api/admin/my/wallet/redeem` | チャージコードの引き換え |
| GET | `/api/admin/auth/registration` | ログイン画面用の公開フラグ |
| POST | `/api/admin/auth/register` | 公開セルフ登録（to C モードかつ設定有効） |

## コンソールページ

- **コスト管理 → プリペイドウォレット**（管理者）：一覧、手動調整、免除トグル、明細ドロワー。
- **コスト管理 → チャージコード**（管理者）：一括生成（一回表示・コピー・エクスポート）と無効化。
- **マイリソース → マイウォレット**（一般ユーザー）：残高カード、コード引き換え、個人明細。

## 注意事項

- オンライン決済、請求書、人民元建て、リクエスト単位の予約は本段階の対象外です。実行中リクエストによるわずかな残高超過は設計上許容されます。
- 登録のレートリミットはプロセス内実装です。多重インスタンス構成では登録エンドポイントの前にエッジでのレートリミットを併用してください。
